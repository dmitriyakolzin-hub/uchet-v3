# CLAUDE.md — Система управленческого учёта и бюджетирования (uchet-v3)

## О проекте

Веб-приложение управленческого учёта и бюджетирования для группы компаний.
Техническое задание: `docs/TZ.md` (рабочее, ведётся по решениям владельца) — читай его
перед началом любой задачи и сверяйся с ним. Если задача противоречит ТЗ или в ТЗ чего-то нет — спроси,
а не додумывай.

Ключевая идея: один журнал операций (шапка + проводки по бухгалтерскому плану
счетов), все отчёты (ОСВ, ДДС, ОПиУ, управленческий баланс, план/факт)
строятся из журнала и раскрываются до проводок.

## Как устроена работа

- Ты работаешь в облачной сессии Claude Code с этим GitHub-репозиторием.
  **Доступа к серверу у тебя нет.** Всё, что касается сервера, ты готовишь
  в виде файлов и инструкций, а выполняет их владелец проекта.
- Владелец проекта — не программист. Объясняй по-русски, коротко и по шагам:
  что сделано, как проверить, какие команды выполнить на сервере.
- Логи и ошибки с сервера владелец приносит в сессию сам. Если для диагностики
  нужна информация с сервера — дай точную команду, которую нужно выполнить,
  и скажи, какой результат прислать.

## Целевое окружение (сервер)

- VPS reg.ru, Ubuntu 24.04, Docker Compose, Nginx.
- Старая система: `/opt/uchet-app/`, домен `cfo-avmv.ru`. **Её не трогать**:
  инструкции не должны менять её файлы, контейнеры, базу и nginx-конфиг
  без явного согласования.
- Новая система: `/opt/uchet-v3/` (клон этого репозитория), домен
  `new.cfo-avmv.ru`, своя база и свои контейнеры (имена контейнеров, тома
  и порты не пересекаются со старой системой; старая занимает 127.0.0.1:8000).
- Секреты только в `.env` на сервере (не в git): `POSTGRES_PASSWORD`,
  `JWT_SECRET` и т.п. В репозитории — только `.env.example` без значений.
  Приложение не должно запускаться, если `JWT_SECRET` не задан.

## Стек

- PostgreSQL 17, суммы только `numeric(18,2)`, дерево ЦФО через `ltree`.
- Python 3.12, FastAPI, SQLAlchemy 2.0, Pydantic v2, Alembic.
- JWT access + refresh, хеши паролей argon2 (pwdlib).
- Фронтенд: SPA без сборки (статические файлы), табличные экраны на
  Tabulator (MIT). Интерфейс на русском.
- Тесты: pytest. Если в облачной среде нет PostgreSQL — установи его
  (или предложи setup-скрипт среды), тесты должны идти на настоящем
  PostgreSQL, а не на SQLite.

## Правила работы

1. Работаем строго по этапам (ниже). Перед началом этапа покажи план
   и дождись подтверждения.
2. Каждое изменение схемы БД — только через миграцию Alembic.
3. Каждый законченный шаг: тесты проходят, коммит с понятным сообщением
   на русском, pull request с кратким описанием «что сделано / как проверить».
4. Права доступа проверяются на сервере в каждом эндпоинте, не только в UI.
5. Деньги: никакого float, только Decimal / numeric.
6. Отчёты и журнал используют одну и ту же серверную функцию отбора проводок,
   чтобы расшифровка всегда совпадала с цифрой отчёта.
7. В конце каждой сессии обнови раздел «Журнал работ» в этом файле.

## Выкладка на сервер

Поддерживай в репозитории файл `deploy/README.md` с пошаговой инструкцией
для владельца (команды копируются целиком):

- первая установка: клонирование в `/opt/uchet-v3`, создание `.env`
  из `.env.example` (с командой генерации секретов), запуск
  `docker compose up -d`, применение миграций, создание первого администратора,
  настройка nginx и HTTPS для `new.cfo-avmv.ru`;
- обновление: `git pull`, `docker compose up -d --build`, миграции,
  проверка, что сервис отвечает;
- откат на предыдущую версию;
- бэкап и восстановление базы.

Каждая инструкция заканчивается проверкой («выполните … — должно вывести …»).

## Этапы

0. **Каркас и безопасность**: структура проекта, compose с отдельной базой,
   секреты из `.env`, Alembic, тесты, `deploy/README.md`, скрипт ежедневного
   бэкапа. Отдельно — короткая инструкция, как закрыть дыру с `JWT_SECRET`
   в старой системе (`/opt/uchet-app`), пока она работает.
   Приёмка: вход с поддельным токеном невозможен, бэкап восстанавливается.
1. **Основа учёта**: организации, юрлица, пользователи, роли и права;
   справочники (план счетов с обязательной аналитикой, статьи с шаблонами
   проводок, контрагенты, договоры, расчётные счета, ЦФО, сотрудники);
   журнал операций со статусами и массовыми действиями; вкладка «Деньги»;
   импорт Excel и банковских выписок 1С.
   Приёмка: месяц реальных операций загружен, проведён и сверен с выпиской.
2. **Отчёты**: ОСВ, ДДС, ОПиУ, управленческий баланс, дебиторка/кредиторка,
   расшифровка любой цифры в журнал.
   Приёмка: итоги сходятся со сверкой за тот же месяц.
3. **Бюджет и план/факт**: ЦФО на 5 уровней, доступ по веткам, версии бюджета,
   сетка ввода (ячейка = плановая операция), план ДДС, отчёт план/факт.
   Приёмка: годовой бюджет введён, план/факт по ЦФО сходится с журналом.
4. **Зарплата и регламент**: сотрудники, начисления, удержания, ведомости,
   выплаты через банк с подтверждением выпиской; регламентные правила,
   основные средства, закрытие периода.
   Приёмка: месяц зарплаты рассчитан, ведомость оплачена и подтверждена.

## Что известно о старой системе (/opt/uchet-app)

- Модули v2 (`backend/api`, `services`, `models`, `schemas`) написаны
  аккуратно, но новая система пишется с нуля по ТЗ. Если владелец загрузит
  старый код в `legacy/`, его можно использовать как образец — не копировать
  бездумно.
- `main.py` старой системы работает со структурой таблицы `operations`,
  которой уже нет: отчёты ОСВ/ДДС/ОПиУ/баланс там не работают.
- В старой системе `JWT_SECRET` не передаётся в контейнер (используется
  значение по умолчанию из `core/config.py`) — токены можно подделать.
- Справочник 175 статей (`unified_articles`) переносится после исправления
  структуры — см. раздел 15 ТЗ.

## Ответы на открытые вопросы ТЗ

Отдельного ТЗ нет: рабочее ТЗ ведётся в `docs/TZ.md` (решения владельца + допущения Claude,
допущения согласуются перед каждым шагом).

- Организации (юрлица одной группы / независимые клиенты): и то и другое; по каждой ведётся учёт и бюджетирование.
- Банки и зарплатные проекты: вводятся вручную в справочники.
- Зарплата: считается в системе, с возможностью загрузки.
- Загрузка из 1С (что и в каком формате): пока ничего, кроме банковских выписок из банк-клиента в формате 1С.
- Валюты: справочник валют, на старте только рубль, курсы вручную.
- Количественный учёт склада: да; количество в проводках и справочники — этап 1, складские отчёты — позже.
- Пять уровней ЦФО и стартовое дерево: Компания → Направление (Производство / Логистика / Торговля /
  Дисконты / Онлайн) → Филиал → Магазин → Подразделение учёта.
- Начальные остатки (дата и источник): вводятся на отдельной вкладке.
- Пользователи и роли на старте: Администратор — всё; Финансовый директор / владелец — всё, кроме
  управления пользователями; CEO — только просмотр; Руководитель ЦФО — черновики по своему ЦФО.
- План счетов: за основу стандартный российский.
- Старая система (`cfo-avmv.ru`): пока не трогаем, решение позже.
